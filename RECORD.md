## 2026-07 — Certificate compliance & PDF refactor (branch `cp12-pdf-design`)
- Wrote per-cert legal-minimum audits (`audit/cp12-field-analysis.md`, `gas-service-field-analysis.md`, `gas-warning-notice-field-analysis.md`) grounded in HSE / GSIUR Reg 36(3) & 26(9) / IGEM-G/11 GIUSP / RIDDOR / Benchmark; discovered the original CP12 audit had analysed a dead renderer and re-based everything on the production path.
- Replaced all three gas-cert AcroForm renderers with programmatic, adaptive "v2" renderers in the CP12 house style (`renderCp12CertificateV2`, `renderGasWarningNoticeV2`, `renderGasServiceV2`); old render fns are thin delegating wrappers. Deleted the dead `src/lib/pdf/cp12-template.ts` and unused `generateCp12FromJob.ts`. Stamped template versions (`*-v2`).
- Added shared issue validators used by both wizard + server (`src/lib/{cp12,gwn,gas-service}/validation.ts`), a tiered `cp12/field-config.ts`, and `cp12/defect-summary.ts`; migration adds `cp12_appliances.flue_location` + `reg_26_9_confirmed` (applied to live DB).
- Compliance behaviour changes: onboarding/issue gate now requires only engineer name + Gas Safe number (company details optional); customer/received-by signature optional (engineer only mandatory); Gas Warning Notice is an optional non-blocking follow-up (not a send-blocker); GWN requires a RIDDOR reference when Immediately Dangerous; CP12 defects auto-compose from per-appliance failed checks.
- Wizard UX: explicit job-type choice + "complete first" order for combined "safety check + service" jobs, cross-cert appliance autofill both directions, dates default to today, boiler readings reordered (pressure/heat-input lead) with clear High/Low groups, conventional (Benchmark) sections marked optional/collapsed.

## 2026-07-14 — Invoice UX, appliance hub, per-appliance GWN, signatures & evidence photos (branch `cp12-pdf-design`)
- Invoice completion routing: a draft invoice's "Review" now opens the output PDF (`/invoices/[invoiceId]/pdf` auto-generates for drafts via `InvoicePdfActions`) instead of the drafting editor; the completion row exposes both Review and Edit. Added a header logo slot to `renderInvoicePdf` (same slot/logic as the cert renderers, optional `companyLogoBytes`; the fetch pipeline is intentionally not wired yet).
- Invoice line-item seeding (`createInvoiceForJob`) now derives from the job's *expected* cert types (`jobs.cert_types` / `job_type` via `expectedInvoiceCertTypesFromJob`), not only issued certs — so a combined "safety check + service" invoice created after the first cert but before the second still bills both (and collapses to the single `cp12_boiler_service` combined line when that standard rate is set). Fixes combined jobs previously billing only the first-issued cert.
- Invoice editor decluttered (`invoice-editor.tsx`): a "Status & terms" card (status + due date), a slimmed bill-to card, one bottom action bar (Save / Email / WhatsApp / Preview), rebuilt line-item rows with an editable quantity + live line total + icon remove, and share actions now persist first so the generated PDF reflects on-screen edits.
- Invoice payment status is now a derived lifecycle — Draft until first sent, then Unpaid, then Overdue automatically from the due date — with a single "Mark as paid" toggle, replacing the manual Draft/Unpaid/Overdue/Paid picker. Emailing/WhatsApping an invoice auto-advances it to Unpaid.
- CP12 wizard restructured around an **appliance hub**: Step 2 is a list of appliances (identity/checks status + safety-classification badge) with always-available Add/Remove; tapping an appliance opens a per-appliance detail (identity → its own inspection/readings/safety checks) that returns to the list; whole-installation (property) checks stand alone on Step 3; signatures remain Step 4. `ApplianceStep` gained an `onlyIndex` prop; per-appliance tab-count helpers were extracted. Completion-checklist "Go" links open the specific appliance.
- **Per-appliance Gas Warning Notices** (GIUSP: one warning notice per dangerous appliance). `getJobCompletionState` emits one GWN row per unsafe appliance (labelled with appliance number + AR/ID), each backed by its own follow-up job carrying `parent_job_id` + `source_appliance_key`/`source_appliance_id`, created idempotently via `ensureGasWarningNoticeJob()` and server-seeded from that specific appliance (`applyCp12SourceDefaultsForGasWarningNotice`). The wizard page creates/opens the follow-up from `?parentJobId=&applianceKey=`; issuing returns to the parent CP12/combined completion page. Warning-notice-only jobs keep the single job-level fallback. `JobCompletionChecklistItem` gained an optional `key` for React uniqueness.
- Customer signature is **opt-in** across CP12, boiler service and GWN — hidden behind an "Add customer signature (optional)" control (engineer signature stays mandatory/visible). GWN gates on handover (customer informed / notice left on premises), never on a customer signature; remote GWN signing was intentionally not built (on-site "notice left" covers the duty).
- **Evidence-photo pipeline fixed.** Uploads previously inserted a non-existent `job_photos.user_id` column (so every upload errored) and stored public URLs against the private `job-photos` bucket. All three upload paths now drop `user_id`, store the raw storage path, and return signed URLs; reads (wizard photo previews, general-works PDF embedding) sign the path via `signJobPhotoUrl`. New `getJobPhotos(jobId)` powers an engineer-only evidence-photo gallery on `/jobs/[id]/complete` (kept internal — not attached to the landlord handover email).
- CP12 unsafe-appliance capture gained research-based quick-select preset chips (GIUSP unsafe situations + standard engineer actions) for Defect notes / Actions taken / Actions required; chips append (de-duplicated) to the editable free text.
